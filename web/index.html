A test stops working the day its questions leak.

Models are trained on the internet, and public test questions are on the internet. A high score can mean a model is capable, or that it has seen the answers. From the outside you can't tell which.

Keeping questions private doesn't fix it. To score a model you have to send it the questions, and then the company running the model has them. And a private test nobody can inspect can be wrong without anyone knowing.

  • 3 Nov 2026Researchers showed the top model on a leading coding benchmark reciting hidden grading rules it was never given. Read the audit
  • Sep 2025The makers of Humanity's Last Exam checked their own answer key and found about 18% of it wrong.
  • 3 Oct 2026NEAR's co-founder listed private-test benchmarks with certified results among the things he wants built.

A question's life, top to bottom

  1. Seal

    A writer's questions are encrypted so that one exact build of the grading program can open them, and only inside secure hardware. We can't read them. The writer's own laptop is the last place they exist in the clear.

  2. Commit

    A fingerprint of the set goes on NEAR before any model is asked anything, with a stake behind the answer key. After that the set can't be swapped or quietly edited.

  3. Run

    Someone pays for a run. The contract starts the grader, the grader checks the set against its fingerprint, asks the model, and marks each answer with plain code. No AI judges another AI.

  4. Record

    Only the score leaves the hardware. The contract stores it as a certificate, pays the writers, and if the model's host could see the questions, marks the set as seen by that company.

  5. Reveal

    After a set number of runs the questions are published. Anyone can check them against the fingerprint, challenge a wrong answer key for a share of the stake, and recompute every score without the bad questions.
